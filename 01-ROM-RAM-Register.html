Q01 · ROM、RAM、Register 三者在嵌入式里到底怎么分工？

你原本的答案（ROM 像硬盘、RAM 像内存、Register 暂存数据）方向是对的，但面试官不会停在"像什么"上——他会接着问"那你的 const 数组在哪""外设寄存器算不算存储器""为什么全局变量的初值要存在 Flash 里"。

面试题干

面试官问

说说嵌入式系统里 ROM、RAM、Register 的概念和作用。
它们各自适合放什么？如果让你指着代码里的一个变量说出它住在哪，你怎么判断？

考察点：掉电特性 / 可写性 / 速度成本梯度 三条线，以及能否落到自己的工程上。
这题是"送分题"，但也是"分层题"——答三句是及格，答出后四条追问才是满分。

先纠一个说法 "ROM 是只读存储器"在 MCU 里要打个补丁：你板子上的 ROM 实际是 Flash，它是可擦写的，只是擦除以"页"为单位、寿命有限（F103 约 1 万次擦写）。叫它 ROM 是历史惯性，真正的只读存储器是出厂固化的 Bootloader 区（0x1FFF_F000）。

30 秒版答案

面试现场就这么说

三者是速度、成本、掉电特性三个维度的取舍：Register 在 CPU 和外设内部，最快、最贵、掉电就丢，放"马上要用的"；RAM（SRAM）在片内，快、贵、掉电就丢，放"运行中会变的"——变量、栈、堆；ROM（Flash）慢、便宜、掉电不丢，放"不会变的"——代码和 const 常量。
一句话：Flash 存不变的，SRAM 存正在变的，寄存器存马上要用的。

思路解析

3.1 先定位：它们分别在哪块硅片上

问"这三个都在 CPU 内部吗"，说明已经开始想物理结构了，这是好方向。准确说法是：只有内核寄存器真正在 CPU 内核内部；Flash 和 SRAM 是挂在总线上的独立存储模块，不算外设；外设寄存器住在外设模块里面。三者同在一片硅上，但彼此没有包含关系。

术语对不上会丢分 ST 手册里，Flash / SRAM 归在 Memory and bus architecture 一章，GPIO / USART 归在 Peripheral 一章 —— 也就是说，"外设"这个词本身就不包含 Flash 和 SRAM。面试时你可以说"在片内"，但说"在 CPU 内"就只对内核寄存器成立。（唯一的小例外：NVIC 和 SysTick 属于内核，却有 PPB 地址 0xE000_0000。）

3.2 它们不是"三种硬盘"，而是挂在同一总线上的三个位置

新手最容易把三者想成"三个不同的柜子"。真实结构是：CPU 里有一小撮寄存器，外面挂一条总线，总线上接了 Flash、SRAM 和外设。CPU 访问它们用的是同一条 load/store 指令，差别只在于它落在哪个地址、那个地址背后是什么器件。

维度ROM（片内 Flash）RAM（片内 SRAM）Register
掉电不丢丢丢（外设配置需重写）
可写方式按页擦除后编程，约 1 万次寿命随时按字节写，不限次数随时写，单周期
访问速度慢（72MHz 需 2 个等待周期 + 预取）快（通常 0 等待）最快（1 个周期）

放什么代码、const 常量、.data 的初值副本全局/静态变量、栈、堆运算中间值、外设控制位

3.5 Register 的两种身份（这道题的第二层）

只说"寄存器暂存指令和数据"会被追问打回。寄存器分两类，性质完全不同：

维度内核寄存器外设寄存器
位置CPU 内核内部各外设模块内部（GPIO/USART…）
有没有地址没有，汇编直接引用 R0有，如 0x4001_0800
C 语言能否用指针访问不能（register 关键字取地址都编译不过）能，必须加 volatile
数量R0–R12、SP、LR、PC + xPSR 等十几个每个外设几十个控制/状态位
谁修改它指令执行时由 CPU 写程序写；硬件也会自己改（如状态位）
volatile 一句话解释 外设寄存器的值会被硬件悄悄改（比如串口收到数据，USART_SR 的 RXNE 自己置 1）。不加 volatile，编译器认为"这个变量没人动过"，会把多次读取合并成一次，或者干脆优化掉 —— 于是你就会遇到"程序一直等不到标志位"这种经典 bug。

① 三个头文件，各管一件事

stdio.h 给 printf，stdlib.h 给 malloc/free，windows.h 给 VirtualQuery。最后这个是本程序的关键——没有它就只能“听说”页属性，没法“查证”。Linux 上对应的是读 /proc/self/maps。

② 四种全局变量，四个落点

const 全局进 .rdata（只读页）；有初值的进 .data；没初值的进 .bss；static 只改变可见范围，段不因此改变。这四行是整页结论的源头。

③ 函数体落在代码段

.text 是“可执行 + 只读”页。这一条解释了为什么改数据可以、改代码不行——不是语言限制，是操作系统把那片内存页标成了只读。

④ 把数字翻译成人话

VirtualQuery 返回的是 Protect 一个 DWORD 掩码，不翻译根本看不懂。注意 PAGE_WRITECOPY——它就是 .data 在 Windows 上的真实属性：写时复制。

⑤ 证据来源：问操作系统

整页所有“只读/可读写”的结论，都由这一行 VirtualQuery 产出。它不是我的推断，是操作系统返回的页表属性——所以那串数字可以当证据用。

⑥ 三种局部数据，三个落点

普通局部变量在栈，malloc 在堆，而字符串字面量 "hello" 不在栈上，它落在只读的 .rdata——这就是“改字面量会崩”的原因。

⑦ 一次打一个，逐个对照

七个 show 覆盖代码段 / 只读数据 / 数据段 / BSS / 栈 / 堆，输出正好是一张完整的对照表。看输出时按这个顺序读，结论自然就出来了。

⑧ 收尾

free 释放堆。本程序不释放也不影响结果（进程退出时系统统一回收），但工程代码里必须成对出现，这是习惯问题，也是面试常问的细节。

滚轮在左侧看代码，点击任意一行 → 右侧对应讲解自动滚到可见并高亮；反过来点右侧卡片，左侧所属代码行一起亮。想复制整段，用右上角按钮。

输出里有个细节别放过：.data 显示的是 PAGE_WRITECOPY 而不是 READWRITE 这就是 Windows 的"写时复制"：镜像里的 .data 页初始是共享只读的，第一次写它时才复制一份私有页，之后就可写。所以它既省内存、又保证各进程互不干扰。结论不变：普通全局变量是"可写"的，const 是"写就崩"的。MCU 上没有 MMU，所以没有这类花活——SRAM 一律可写，Flash 一律写不了。

在你自己的工程里怎么验证（Keil）

  • 看四个数：编译输出最后一行 Program Size: Code=xxxx RO-data=xxxx RW-data=xxxx ZI-data=xxxx。
    Flash 占用 = Code + RO-data + RW-data；RAM 占用 = RW-data + ZI-data。这条几乎必问。
  • 看地址：Debug 里把变量加到 Watch，右键看它的地址 —— 0x0800_xxxx 就是 Flash，0x2000_xxxx 就是 SRAM。
  • 看总量：Options for Target → Target 里的 IROM1 / IRAM1 就是 Flash 与 SRAM 的起始地址和大小（MDK5 口径，菜单字样以你本机为准）。
  • 看明细：Options for Target → Listing 勾上 Linker Listing 的 Memory Map，编译后在 Listings 下找 .map，能看到每个函数、每个变量具体放在哪一段。

关键要点

  • 三条判断线：掉不掉电、能不能随时写、快不快。ROM=不丢/要擦/慢，RAM=丢/随便写/快，寄存器=丢/随便写/最快。
  • MCU 上的 ROM 是 Flash：可擦写、按页擦、寿命约 1 万次。"只读"是历史叫法，真正只读的是出厂 Bootloader 区。
  • 一个变量可能有两份数据：有初值的全局变量，初值在 Flash（.data 副本），运行副本在 SRAM。
  • 寄存器分两类，且只有它在 CPU 内：内核寄存器没有地址（汇编直接用），外设寄存器有地址（C 指针 + volatile）。Flash / SRAM 虽在片内，但不在 CPU 里、也不算外设。
  • Flash 和 RAM 四个数：Flash=Code+RO+RW，RAM=RW+ZI。这就是面试官问"你这个工程占多少内存"的标准答法。

面试官会接着问什么

追问怎么答（一句到位）
ROM 不是只读吗，为什么还能烧程序？MCU 里用的是 Flash，可擦写；只是擦除以页为单位、寿命有限（F103 约 1 万次）。
为什么全局变量的初值要放 Flash？RAM 掉电就丢，初值必须固化；上电时启动代码把 .data 拷进 SRAM、把 .bss 清零，之后才跳 main。
栈和堆在哪里？会不会撞车？都在 SRAM。栈从 RAM 顶端向下长，堆从 .bss 之后向上长，中间的空闲区就是安全余量，撞上就栈溢出。
外设寄存器算存储器吗？物理上是触发器阵列，不是存储器；但被映射到地址空间，所以能当内存访问 —— 叫内存映射 I/O。
为什么必须加 volatile？值会被硬件改，编译器不知道，会合并或消除访问。加了它，每次读都真的去读地址。
往 0x0800_0000 写数据会怎样？F103 没有 MMU/MPU，不会像 PC 那样报"段错误"，而是总线错误 → HardFault，同时 Flash 控制器在 FLASH_SR 里置 PGERR/WRPRTERR。
72MHz 时 Flash 为什么要配等待周期？Flash 读取速度跟不上 CPU 主频，需 2 个等待周期并开启预取缓冲；配错会跑飞或读数错。

扣分回答

  • 只停在"ROM 像硬盘、RAM 像内存"的类比，说不出 Flash/页擦除/寿命。
  • 把 Register 一句"暂存数据的硬件"带过，没区分内核寄存器和外设寄存器。
  • 说"局部变量在 Flash 里"（因看到 const 就以为局部也进 Flash）——局部 const 仍在栈上。
  • 说"栈向上长、堆向下长"（记反了）。

加分动作

  • 主动说出"一个变量的初值在 Flash、运行副本在 SRAM"。
  • 主动给出 Program Size 四个数与 Flash/RAM 的换算。
  • 把"无 MMU ⇒ 写 Flash 是 HardFault 而非段错误"点出来，直接区分于 PC 经验。
一句话带走的记忆锚

Flash 存"不会变的"，SRAM 存"正在变的"，寄存器存"马上要用的"。三者不是三种硬盘，是速度、成本、掉电三条线拉出来的三个位置。
